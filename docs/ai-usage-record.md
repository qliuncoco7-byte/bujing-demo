## 2. 用户本人的判断与决定

- 提出并确定补镜功能方向：做剪辑器内、围绕当前时间线的辅助画面补入，不做宽泛的随手成片。
- 确定素材库检索与 AI 生成两条路径，共用内容需求与风格条件。
- 对视频类型、表现风格与氛围的适配提出要求；界面的风格理解不只是色温、滤镜或颗粒。
- 确定轻量授权方式：原片解析由用户主动开启，允许跳过，跳过不是永久拒绝，之后可以再次开启。
- 明确视频、PRD 等交付要求与细节；查看 Demo 和文档后继续提出调整，修改 PRD。
- 提供第 4 页「本人喜欢的产品」的真实经历，并确认 Demo 的模拟范围与展示边界。

这些决定构成了产品的范围和验收标准；AI 没有替用户决定产品方向。

## 4. Claude Code（本会话）的实际工作

### 工程实现

- 使用 React 19 + Vite + TypeScript 实现纯前端剪辑工作区：视频预览、简化时间线、右侧补镜面板。
- 用 Canvas 2D 编写程序动画场景：漫画风城市街道、林荫道、树冠特写、模拟实拍观感树冠、空档占位；支持播放、暂停、拖动标尺、上下文连续预览。
- 实现补镜状态机：补镜入口、空档选择、需求输入、可选原片解析、可修改摘要、素材库/AI 生成双路径、候选单独预览、上下文预览、插入、撤销、替换、重置。
- 实现生成路径的预制版本：V1 强风、V2 微风；支持一次“强风改微风”的明确修改；加载状态允许切回素材库；失败由独立演示开关触发，保留条件并可重试。
- 使用 macOS `say -v Tingting` 与 `afconvert` 自制口播音频，并按时间线对齐三句口播；口播轨道连续，插入后保留原口播。
- 所有示例画面均为自制 Canvas 程序动画；“实拍观感”素材明确标注为模拟，不冒充真实拍摄或授权素材；“AI 生成”明确标注为预制示例。

### 验证与质量检查

- 使用 Playwright + 本机 Chrome 编写并运行 `scripts/functional_check.mjs`，逐项断言：
  - 无登录初始项目、4 秒空档与常驻补镜入口；
  - 时间线播放推进与口播音频加载；
  - 解析关闭/开启、摘要可修改、关闭后条件不再用于新请求；
  - 素材库与生成页签切换保留需求；
  - 超范围输入提示与生成禁用；
  - 生成加载、后台完成提示、结果自动露出；
  - 候选单独预览与上下文预览；
  - 插入后时间线与主预览变化、⌘Z 撤销；
  - 替换后用 toast 撤销恢复上一版；
  - 重置、失败、重试。
- 使用 Playwright 截图进行视觉检查，覆盖 1440×900、1280×800、1024×768 与 1920×1080。
- 当前执行机器的系统输出处于静音状态（`osascript` 显示 `output muted: true`），媒体时钟在本地与线上浏览器中均未推进。因此**未完成听感确认**；已确认音频文件可加载、时长为 15.07 秒，并由播放/插入交互触发。需在真实有声环境复核口播。
- 使用 Playwright 录屏（1280×800，约 2 分 06 秒），叠加操作光标与步骤字幕，再用自制 TTS 旁白与 ffmpeg 合成为 MP4；录屏基于真实运行的生产构建，不是静态拼接。
- 使用无头 Chrome 将五页说明 HTML 导出为 PDF，并校验页数为 5；说明 HTML 在屏幕上为连续长文并带锚点目录，打印时保持 A4 分页。
